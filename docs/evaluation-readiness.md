## 1. 기획 (1-1 ~ 1-3)

기획 문서·요구사항 정의서·화면 흐름도 기반 항목으로, 기획/총괄 담당 영역입니다.

- 1-1 문제 정의·필요성: **확인 필요** — 진료기록 기반 복약안내라는 문제 정의는 명확하나, 정량 근거(시장/사례) 문서화 여부 확인 필요
- 1-2 요구사항 분석: **확인 필요** — 기능/비기능 요구사항 구분 및 우선순위 문서 확인 필요
- 1-3 기획 문서 양식: **확인 필요** — 화면 흐름도·기능 정의·데이터 흐름 포함 여부

## 2. 설계 (2-1 ~ 2-3)

- 2-1 기술 스택: **양호** — FastAPI/Tortoise ORM/PostgreSQL/Redis/Docker. LLM은 OpenAI API. 선정 근거 문서화하면 5점
- 2-2 확장성: **양호** — 서비스/DTO/라우터 계층 분리, ai_worker 분리(잡 큐). 모듈 단위 확장 가능 구조
- 2-3 아키텍처: **양호** — apis/services/models/dtos 계층 명확, 의존성 분리됨

## 3. AI (3-1 ~ 3-4)

- 3-1 모델 성능 검증: **보강됨** — LLM API 기반이라 자체 학습 지표는 없으나, safety_filter 분류기 성능을 정량 측정(Recall 1.0/Specificity 1.0, 검증세트 23건). [PR #129]
- 3-2 비동기 처리: **양호** — LLM 호출 AsyncOpenAI 전환으로 이벤트 루프 블로킹 제거. [PR #125]
- 3-3 결과 편차 최소화: **완료** — LLM 호출 고정 seed 적용 + 재현성 검증 테스트. [PR #119]
- 3-4 피드백 반영 구조: **완료** — 수집·저장 + 집계 조회(GET /feedbacks/summary)로 개선 활용 구조. [PR #120]

## 4. UI/UX (4-1 ~ 4-3)

FE 구현 영역으로, FE 담당 확인이 필요합니다.

- 4-1 화면 흐름: **확인 필요** — 주요 기능 3~5단계 접근성. FlatList 전환으로 리스트 UX 개선됨 [PR #124]
- 4-2 일관된 경험: **확인 필요** — 전체 화면 접근성 속성(accessibilityRole/Label) 추가됨 [PR #127]. 오프라인 배너 등 일관 처리 [PR #123]
- 4-3 액션 단계: **확인 필요** — FE 네비게이션 흐름 확인 필요

## 5. API (5-1 ~ 5-5)

- 5-1 P95 Latency 3초: **Sprint 6** — 실측은 배포 환경에서. async 전환으로 사전 대비됨. locust/ab 측정 필요
- 5-2 HTTP Method 분리: **양호** — GET 22·POST 17·PATCH 9·DELETE 5·PUT 2, REST 원칙 준수
- 5-3 배포 환경 동작: **Sprint 6** — deploy.yml(EC2) 존재, 실배포·동작 확인 필요 (6/12 데드라인)
- 5-4 인증/인가: **양호** — JWT access/refresh 구현, 토큰 백엔드 분리
- 5-5 비동기 응답속도: **양호** — async I/O + ai_worker 비동기 잡 처리. [PR #125]
