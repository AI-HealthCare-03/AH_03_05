# 보안 정책 문서 — 민감정보 보호 및 로그 마스킹 (REQ-SEC-002)

## 1. 개요
사용자의 민감정보(OCR 원문, 건강정보, 인증 토큰, API Key)는 일반 로그에 출력하지 않는다.
배포 환경에서는 HTTPS 적용을 목표로 한다.

---

## 2. 민감정보 마스킹 대상 항목

| 항목 | 분류 | 처리 방식 |
|------|------|-----------|
| OCR 원문 (`ocr_text`, `ocr_edited_text`) | 의료 민감정보 | 로그 출력 제외 |
| 건강정보 (`chronic_diseases`, `allergies` 등) | 개인 건강정보 | 로그 출력 제외 |
| JWT Access Token | 인증 토큰 | 로그 출력 제외 |
| JWT Refresh Token | 인증 토큰 | 로그 출력 제외 |
| 비밀번호 (`password`, `password_hash`) | 인증 정보 | 로그 출력 제외, DB 해시 저장 |
| OPENAI_API_KEY | 외부 API Key | 환경변수로만 관리, 로그 출력 제외 |
| MFDS_API_KEY | 외부 API Key | 환경변수로만 관리, 로그 출력 제외 |

---

## 3. 로그 마스킹 처리 방식

### 3.1 현재 적용 방식
- 민감정보는 로그 출력 시 포함하지 않는다.
- API Key 및 토큰은 환경변수(`.env`)로만 관리하며 코드에 하드코딩하지 않는다.
- 비밀번호는 `bcrypt` 해시로 저장하며 평문은 어디에도 저장하지 않는다.

### 3.2 코드 리뷰 점검 항목
- [ ] OCR 원문이 로그에 출력되지 않는지 확인
- [ ] 건강정보 필드가 로그에 출력되지 않는지 확인
- [ ] 토큰 값이 로그에 출력되지 않는지 확인
- [ ] API Key가 코드에 하드코딩되지 않는지 확인

---

## 4. HTTPS 적용 계획

| 구분 | 내용 |
|------|------|
| 현재 상태 | 로컬 개발 환경 — HTTP |
| 배포 목표 | HTTPS 적용 (nginx reverse proxy + SSL 인증서) |
| 적용 방식 | Let's Encrypt 또는 자체 서명 인증서 활용 예정 |
| 미적용 시 | 배포 전 적용 계획 및 사유 문서화 |

---

## 5. 향후 계획 (Sprint 3 / 상용화)
- 컬럼 단위 암호화 (민감 건강정보 필드)
- 키 관리 시스템 도입
- 감사 로그 고도화 (REQ-COM-009)
