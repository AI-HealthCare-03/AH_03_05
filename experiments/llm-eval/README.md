# 복약 안내 가이드 LLM 품질 평가

LLM(gpt-4o-mini) 기반으로 생성되는 복약 안내 가이드의 출력 품질을 정량 평가하는 실험.

## 배경 / 문제

MediPT의 복약 가이드는 상용 LLM API로 생성된다. 이런 LLM 기반 출력은
"정답 라벨"이 없어 정확도·F1 같은 전통적 지표를 적용할 수 없고, 품질을
"좋다 / 자연스럽다" 같은 모호한 표현으로만 기술하기 쉽다.

→ 자체 평가 데이터셋 + 채점 루브릭 + LLM-as-judge로 출력 품질을
정량 지표(축별 1~5점)로 환산한다.

## 방법
dataset.json  →  generate_guide()  →  judge(gpt-4o)  →  results.json
(8개 케이스)      (gpt-4o-mini)        (루브릭 4축)        (점수+근거)

1. 평가 데이터셋 (dataset.json): 대표 복약 시나리오 8건
   (고혈압·당뇨 단독 / 다약제 / 고령 / 정보 누락 / 상호작용 주의 / 약물 없음 등 경계 케이스 포함)
2. 루브릭 (rubric.md): 정확성·안전성·개인화·완전성 4축, 각 1~5점
3. LLM-as-judge (run_eval.py):
   - 생성 모델 = gpt-4o-mini (서비스와 동일)
   - judge 모델 = gpt-4o (상급 모델로 평가해 self-evaluation 편향 완화)
   - judge가 입력(환자 정보)과 출력(가이드)을 함께 보므로 정답 없이도 정확성·근거성 평가 가능

## 실행

```bash
OPENAI_API_KEY=... PYTHONPATH=. uv run python experiments/llm-eval/run_eval.py
```

결과는 results.json(케이스별 점수+근거)과 콘솔 축별 평균으로 출력.

## 결과

LLM-as-judge(gpt-4o-mini) 채점, 8개 케이스 평균:

| 평가 축 | 평균 (/5) |
|---------|-----------|
| 정확성 | 4.88 |
| 개인화 | 4.75 |
| 완전성 | 4.62 |
| 안전성 | 4.25 |
| **종합** | **4.62** |

### 관찰 / 개선점

- **정확성(4.88)이 가장 높음** — 입력 약품 정보를 정확히 반영, 환각 거의 없음. 약품 컨텍스트 주입이 효과적으로 작동.
- **안전성(4.25)이 가장 낮음 → 핵심 개선 대상.** 채점 근거 분석 결과 일관된 패턴 발견:
  - 다약제·상호작용 케이스는 경고+상담 안내가 모두 포함되어 5점.
  - 저위험 단일 약물 케이스(고혈압·당뇨 단독)는 의사 상담 안내는 있으나 경고 메시지(warning_message)가 누락되어 4점.
  - 즉 "경고할 위험이 뚜렷한 케이스"만 warning을 채우고, 단순 케이스는 비우는 경향.
- **경계 케이스(약물 없음, 4.00)** — 현재 복용 약물이 없다는 점이 응답에 명확히 반영되지 않음.

### 개선 방향 (측정 기반)

1. **안전성** — 프롬프트에 "위험도와 무관하게 모든 가이드에 기본 안전 고지(임의 중단 금지, 이상반응 시 전문가 상담)를 포함하라"를 명시 → 재측정으로 점수 변화 확인.
2. **경계 케이스** — 약물 없음 입력 시 "현재 복용 약물 없음"을 명시하도록 분기.

→ 개선 후 동일 데이터셋으로 재평가하면 "안전성 4.25 → X.X" 형태의 정량적 개선 효과를 제시할 수 있다.

## 개선 실험: 안전성 (compare_safety.py)

초기 평가에서 안전성이 최저(저위험 단일 약물 케이스의 warning 누락)로 나와,
프롬프트에 "위험 유무와 무관하게 모든 가이드에 기본 안전 고지를 포함"하는
규칙을 추가하고 동일 데이터셋으로 A/B 재측정했다.

| 조건 | 안전성 평균 (/5) |
|------|------------------|
| A. baseline (현재 프롬프트) | 3.25 |
| B. improved (기본 안전 고지 강제) | **4.50** |
| 차이 | **+1.25** |

케이스별로 보면, 위험이 뚜렷한 케이스(상호작용·정보누락)는 원래 경고를 잘
포함해 변화가 적었고(5→5, 4→4), **저위험 단일 약물 케이스에서 크게 개선**됐다
(고혈압 3→5, 당뇨 2→4, 항생제 3→5, 약물없음 2→4). 즉 "경고할 위험이 뚜렷할
때만 warning을 채우던" 약점이 기본 안전 고지 강제로 해소됐다.

→ 측정으로 약점을 발견하고(안전성 최저), 원인을 근거로 특정한 뒤(warning 누락),
프롬프트를 개선해 정량적 효과(+1.25)를 입증한 사례.

(judge가 안전성만 집중 평가하도록 프롬프트를 좁혀 baseline 절대값은 종합 평가
때(4.25)보다 낮으나, 동일 조건 A/B 비교이므로 개선 폭은 유효하다.)

## 한계

- **judge가 생성과 동일 모델(gpt-4o-mini)** — 현재 OpenAI 프로젝트 키가 mini만 접근 가능해 self-evaluation 구조. 상급 모델(gpt-4o 등) 접근 시 평가 신뢰도를 더 높일 수 있다.
- 평가 케이스 8건으로 통계적 일반화에는 부족 (소재 검증·파이프라인 구축 목적).
- judge LLM의 판단 편향 가능성 — 사람 채점과의 일치도(상관) 검증으로 보완 가능.
- 생성·채점 모두 temperature=0 / seed 고정으로 재현성은 확보.
